# 第 7 章 · 屏幕适配与坐标换算

**本章目标**：搞懂"逻辑坐标"和"屏幕像素"的区别；让台面跟着窗口变大变小；把鼠标点击的位置准确换算成台面坐标；让画面在高清屏上不糊。

**开始之前**：第 5、6 章 —— 已经能画出桌子和球。

---

## 1. 一个真实的麻烦

你的画布是 `1120 × 620` 逻辑像素。但用户屏幕有 1366、1440、1920、手机 375……你把画布写死 1120，在 1440 屏幕上只占中间一小块，两边留黑边；在手机上又撑出横向滚动条。

如果每个尺寸都重算一遍坐标，物理、碰撞、袋口全要跟着变——**这是灾难**。

所以全行业统一的解法：**内部永远用一套固定的"逻辑坐标"算，显示的时候整体缩放。**

```
逻辑坐标（永远不变）          屏幕显示（随窗口变）
1120 × 620      ──缩放──→     比如 960 × 531
球心 (560,310)                屏幕 (480, 265.5)
```

**物理、规则、AI 全部只认逻辑坐标。** 屏幕多大跟它们没关系。这就是为什么 `js/config.js` 里所有数字都按 1120×620 写。

---

## 2. 让画布跟着窗口走

CSS 控制"显示多大"，画布内部仍是 1120×620：

```css
canvas {
  display: block;
  width: 100%;        /* 跟着父容器宽度 */
  height: auto;       /* 高度按比例自动算 */
}
```

这样画布在页面上被拉伸/压缩，但里面还是那么多格。**球不会被"压扁"，因为我们保持了宽高比。**

项目里 `table-col` 的宽度由布局决定，画布 `width:100%`，所以窗口变化时台面自动跟着变，逻辑坐标一点没动。

---

## 3. 点击位置怎么换算回来

这是最容易错的地方。用户点屏幕 `(clientX, clientY)`（相对浏览器窗口），你要知道它对应台面上的哪个逻辑坐标。

```js
const rect = canvas.getBoundingClientRect();   // 画布在屏幕上的位置和大小

function pointerPos(e) {
  return {
    x: (e.clientX - rect.left) / rect.width  * VIEW_W,
    y: (e.clientY - rect.top)  / rect.height * VIEW_H
  };
}
```

四步：

1. `rect.left / rect.top`：画布左上角在屏幕上的位置
2. `e.clientX - rect.left`：点在画布内偏右多少（屏幕像素）
3. `/ rect.width`：变成比例（0 ~ 1）
4. `* VIEW_W`：乘回逻辑宽 1120，得到逻辑 x

同理 y。**这就是 `js/input.js` 第 8–14 行的 `pointerPos`，一字不差。**

> **坑**：`rect` 不能只在启动时算一次。窗口尺寸变了、页面滚动了，`rect` 就过期了。所以每次事件里现取（`getBoundingClientRect()` 很便宜）。

---

## 4. 高清屏为什么糊

`devicePixelRatio`（DPR）是"一个 CSS 像素里塞了几个物理像素"。普通屏是 1，MacBook / 手机常见 2 或 3。

如果画布 `width=1120`，在 DPR=2 的屏上每个像素被拉成 2×2 的方块 → 边缘发虚、字发糊。

解法：**内部按 DPR 放大，CSS 尺寸不变。**

```js
function fitCanvas() {
  const dpr = window.devicePixelRatio || 1;
  canvas.width  = VIEW_W * dpr;
  canvas.height = VIEW_H * dpr;
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0);   // 之后照逻辑坐标画
}
```

`setTransform(dpr, 0, 0, dpr, 0, 0)` 的意思是"你后面说画到 (560,310)，实际落到物理像素 (1120,620)"。

**关键：画布 width 改了以后，所有绘制状态会重置**（颜色、线宽、变换全部回到默认）。所以要么在 resize 后重设一次，要么每帧开头重设。项目 `js/canvas.js` 的 `setupCanvas()` 就是这么干的。

---

## 5. 缩放的副作用：字号和线宽

你在逻辑坐标里写 `lineWidth = 2`，画面被缩小到 60% 时，实际只有 1.2 像素宽 → 看起来像断线。

所以项目里有些地方要"反算"：

```js
const cssScale = canvas.getBoundingClientRect().width / VIEW_W;  // 比如 0.6
ctx.lineWidth = 1.6 / cssScale;             // 显示时正好 1.6
ctx.font = `${clamp(12 / cssScale, 13, 30)}px sans-serif`;
```

`1.6 / 0.6 ≈ 2.67`，缩小后显示成 1.6。**字号同理**，还要 `clamp` 兜底，防止小屏上字大得离谱。

---

## 6. 坑

1. **改了 `canvas.width` 忘了重设样式/变换**，画面全糊或全白。
2. **用 `offsetX / offsetY` 算坐标。** 在缩放过的画布上它给的是"显示像素"，不是逻辑坐标，务必用 `getBoundingClientRect` 换算。
3. **`style.width` 和 `width` 混用。** 前者是显示尺寸，后者是画布格数。
4. **忘了监听 `resize`。** 项目里窗口变化时只需让 CSS 去处理，不必重算逻辑；但如果你真要重设 DPR，就得在 `resize` 里重跑一次 `fitCanvas()`。

## 7. 练习

1. 给画布加 `width: 80%`，刷新，用 `getBoundingClientRect()` 打印 `width` 和 `VIEW_W`，算出缩放比例。
2. 在画布上 `addEventListener('pointerdown')`，打印 `pointerPos(e)`，点画布左上角看是不是 `(0,0)` 附近、点右下角是不是 `(1120,620)` 附近。
3. 把 `devicePixelRatio` 相关的三行注释掉，在本机（如果是高分屏）对比截图：球号是不是变糊了。
4. 把 `lineWidth` 改成 `2 / cssScale`，缩到 50% 窗口看看线是不是还清楚。
