# 第 11 章 · 鼠标与触摸

**本章目标**：用指针事件实现"按住往回拖 → 松手出杆"；弄懂为什么瞄准方向是"拖拽的反方向"；把拖动距离换算成 0~100% 的力度。

**开始之前**：第 7 章（坐标换算）、第 8 章（有速度就能动）。

---

## 1. 一套事件同时管鼠标和手指

老办法是 `mousedown` / `mousemove` 管鼠标，`touchstart` / `touchmove` 管手指，两套代码。现在有更省事的：**Pointer Events**，一套管全部。

```js
canvas.addEventListener('pointerdown', onPointerDown);
canvas.addEventListener('pointermove', onPointerMove);
canvas.addEventListener('pointerup', onPointerUp);
```

| 事件 | 什么时候触发 |
| --- | --- |
| `pointerdown` | 手指/鼠标按下 |
| `pointermove` | 按住并移动 |
| `pointerup` | 抬起 |
| `pointercancel` | 系统把这次触摸"抢走了"（第 12 章细说） |

注意：**没按下时也会收到 `pointermove`**（鼠标在自己移动），所以要用一个变量记住"这次拖拽只有按下的那个指针才算"：

```js
let activePointer = null;

function onPointerDown(e) {
  if (activePointer !== null) return;   // 已经有手指在拖了，忽略第二根
  activePointer = e.pointerId;
  ...
}

function onPointerMove(e) {
  if (e.pointerId !== activePointer) return;   // 不是同一个手指/鼠标
  ...
}

function onPointerUp(e) {
  if (e.pointerId !== activePointer) return;
  activePointer = null;
  ...
}
```

`e.pointerId` 是这次触摸的编号，多点触控时靠它区分。

## 2. 把指针"拴"在画布上

用户可能拖到画布外面再松手。不处理的话，`pointerup` 会落在别的元素上，游戏就"卡在拖拽状态"。

```js
if (canvas.setPointerCapture) {
  try { canvas.setPointerCapture(e.pointerId); } catch (err) { /* 忽略 */ }
}
```

`setPointerCapture` 的意思是"这个指针之后的所有事件都发给我，不管它跑到哪"。这样拖到浏览器外面也能正常收尾。

`try / catch` 是因为个别环境（合成事件、老内核）会抛异常——**背景：我们真机上遇到过"按下后整个游戏再也按不动"，就是因为这里抛错打断了后续逻辑。** 一行 `try` 换来稳。

## 3. 方向：为什么是"反方向"

打台球是**把杆往回拉，然后往前送**。玩家最直觉的操作是：

> 按住母球往左拖——球杆在右边——松手，球往**右**跑。

所以方向取反：

```js
const dx = cue.x - p.x;      // 母球位置 - 指针位置
const dy = cue.y - p.y;
const d = Math.hypot(dx, dy);
if (d > 0.5) {
  state.aimDir = { x: dx / d, y: dy / d };   // 单位方向
}
```

拖得越远，方向越明确；`d / d` 归一化让方向向量长度恒为 1，方便后面乘速度。

---

## 4. 距离 → 力度

```js
const MAX_DRAG = 84;                       // 拖满力需要拖多远
const pull = Math.max(0, d - BALL_R * 1.6); // 扣掉球本身的半径
state.power = clamp(pull / MAX_DRAG, 0, 1);
```

- `d - BALL_R * 1.6`：从球心往外 22 像素内不算力度（否则按住球心就是 0% 还挺好，但手指按球的边缘会直接给一截力）
- `/ MAX_DRAG`：84 像素 = 100%
- `clamp`：超过 84 也不会超过 100%

**`MAX_DRAG` 是"手感"参数，不是物理参数。** 项目早期是 250，玩家反馈"要拖好远才满力，手累"，改成 84 后舒服多了。这类数字只能试。

## 5. 松手出杆

```js
function onPointerUp(e) {
  if (e.pointerId !== activePointer) return;
  activePointer = null;
  if (!state.aiming) return;
  state.aiming = false;

  const power = state.power;
  if (power > 0.04) {
    shoot(power);        // 真的打
  } else {
    state.power = 0;     // 太轻，当作"点了一下"，不出杆
  }
}
```

`0.04` 的阈值是为了防误触：手指在球上轻轻一碰（`power` 只有 1%~2%）不该把球打飞。

出杆本身只做一件事——**给母球一个速度向量**：

```js
const speed = Math.max(MIN_SHOT_SPEED, MAX_SPEED * power);  // 150 ~ 1250
cue.vx = state.aimDir.x * speed;
cue.vy = state.aimDir.y * speed;
```

`MAX_SPEED = 1250` 是满力球速（逻辑像素/秒）。按台面 1000 宽算，满力一杆能横穿台面还带反弹——跟真实手感对上。

## 6. 还有一个"轻点"要处理

如果你只处理拖拽，会发现点一下袋口想把黑八指定到那个袋时，程序把它当成"力度 0 的拖拽"。所以 `pointerup` 里要区分：

```js
if (!state.moved && isOnEight(state.turn) && state.ruleSet === 'us') {
  const idx = pocketAt(p.x, p.y);
  if (idx >= 0) { state.calledPocket = idx; return; }   // 指定袋，不出杆
}
```

`state.moved` 是"这次拖拽移动超过 6 像素了吗"，在 `pointermove` 里更新：

```js
if (Math.hypot(p.x - downPos.x, p.y - downPos.y) > 6) state.moved = true;
```

6 像素是"手指抖一下"的容差。

---

## 7. 坑

1. **`pointermove` 只绑在画布上。** 拖出画布就断了 → 用 `setPointerCapture` 或把 move/up 绑到 `window`。
2. **忘了 `e.preventDefault()`。** 手机上拖拽会顺带滚动页面、甚至触发浏览器的下拉刷新。事件监听加 `{ passive: false }` 才能拦。
3. **`pointerdown` 里 `return` 太晚。** 一旦提前 `return` 却没清 `activePointer`，之后所有操作都失效（"游戏卡死"的经典原因）。
4. **`e.clientX` 直接当逻辑坐标用。** 必须走第 7 章的 `pointerPos` 换算。

1. 在画布上按住拖，用 `console.log` 打印 `aimDir` 和 `power`，确认"往左拖 → 方向朝右"。
2. 把 `MAX_DRAG` 改成 40，感受"很容易满力"。
3. 把出杆阈值 `0.04` 改成 `0.3`，感受"轻轻拖没反应"。
4. 拖到画布外面松手，看球是否还能正常打出去（验证 `setPointerCapture`）。
