# 第 22 章 · 番外：做一个跳球挑战

**本章目标**：在能玩的八球旁边，再做一个**独立的小玩法**——跳过挡球，把指定的球送进指定的袋。你会学到怎么"另起一个模块"、怎么在俯视图里表示"球飞起来了"、怎么算偏角关的瞄准点，以及难度该往哪儿加。

**开始之前**：第 8～11 章（动画循环、速度、碰撞、拖拽瞄准）。不用全记住，能看懂 `vx / vy` 是速度、`ctx` 是画笔就够了。

---

## 1. 为什么不直接改主玩法

主玩法是"两个人轮流打 16 颗球、有规则有犯规"；跳球挑战是"一个人、一颗母球、几颗挡球、一杆一关"。**规则完全不同**，硬塞进主状态机里，两边都会变得难维护。

还有两个很实在的技术原因：

1. `js/render.js` 里画台面的函数直接用全局 `ctx`，它不认识"另一张台面"
2. `js/physics.js` 里所有球默认都贴在台面上（`z = 0`），而跳球需要"球离地、有高度、有影子"——这是主物理里根本没有的维度

所以我们**另起一份**：`js/jump.js`，自带一张台面、一套物理、一个循环。它和主玩法只握一次手——打开、关闭。

代码形状是"自己调用的匿名函数"（IIFE），写起来像这样：

```js
(function () {
  const overlay = document.getElementById('jumpMode');
  if (!overlay) return;          // 没这个浮层就直接不启动

  // 这里面的所有变量都是"这一个模块私有"的
  let s = null;

  function open() { /* 显示浮层、开始计时 */ }
  function close() { /* 隐藏浮层、恢复主局 */ }

  // 只把需要外面用的东西挂到 window 上
  window.JumpChallenge = { open, close, step, state: () => s };
})();
```

好处很直接：**里面的变量一个都不会漏到全局**；主玩法的 `state`、主循环、规则一行都不用改；将来不想要这个玩法，删掉一个文件、一个按钮就干净了。

> 这就是第 4 章讲的"分层"在真实项目里的样子：**能隔离的就隔离，别让新功能有机会影响老功能。**

## 2. 俯视图里，怎么表示"球飞起来了"

二维画面上没有第三个方向，所以我们用两个东西配合：

- **物理里**：给球一个 `z`（球心离台面的高度）和 `vz`（向上速度），只受重力
- **画面上**：把球心往上抬一点、把球画大一点、影子缩小变淡

```js
const LIFT = 0.30;        // 一米的高，画面上抬多少
const AIR_SCALE = 320;    // 越接近 0，飞起来显得越大

// 画的时候（简化版）
const sy = b.y - b.z * LIFT;              // 屏幕上的 y：抬高了
const r = BALL_R * (1 + b.z / AIR_SCALE); // 高的球画大一点点
```

起跳角度**写死 33°**，玩家只控制"往哪打"和"用多大力"：

```js
const G = 1500;                       // 重力
const ANGLE = 33 * Math.PI / 180;     // 固定仰角
const S_MIN = 360, S_MAX = 1250;      // 力度 0% 和 100% 对应的杆速

cue.vx = ux * speed * Math.cos(ANGLE);
cue.vy = uy * speed * Math.cos(ANGLE);
cue.vz = speed * Math.sin(ANGLE);
```

只给两个自由度（方向、力度），是因为**三个自由度玩家算不过来**。这也是"手感"的来源：少一个选项，反而更好控。

**落地之后**就交给普通的滚动：吃摩擦、慢慢停、撞库反弹、进袋判赢。判断"真的越过去了"要看高度，不能只看位置：

```js
const CLEAR_Z = BALL_R * 2;          // 球心抬到两颗球高，才算跨过挡球
```

## 3. 假想球：偏角关的瞄准点（本章重点）

第 1 关是"母球 → 挡球 → 目标球 → 袋口"一条直线，闭着眼也能打进。

第 2 关我们把袋口偏了 15°。这时候目标球要**沿"球心 → 袋口"那条线走出去**，母球就得在一个特定的点上碰到它——那个点叫**假想球**：

```
目标球 ●────────→ 袋口
      ╲
   假想球 ○   ← 母球要滚到这个圈里，目标球才会朝袋口走
        ↑
      母球
```

它就是"从目标球沿袋口方向往回退两个球半径"：

```js
const px = pocket.x - target.x;
const py = pocket.y - target.y;
const pd = Math.hypot(px, py) || 1;
const ux = px / pd, uy = py / pd;

const ghost = { x: target.x - ux * BALL_R * 2, y: target.y - uy * BALL_R * 2 };
```

顺手算一个"打薄了多少度"（台球里叫**薄厚度**），后面用它决定要不要画这个圈：

```js
const v1x = cue.x - target.x,    v1y = cue.y - target.y;      // 母球来的方向
const v2x = pocket.x - target.x, v2y = pocket.y - target.y;   // 目标球要去的方向
const cosA = (v1x * v2x + v1y * v2y) / (Math.hypot(v1x, v1y) * Math.hypot(v2x, v2y));
const cutDeg = Math.abs(180 - Math.acos(cosA) * 180 / Math.PI);
```

第 1 关算出来是 0.2°，第 2 关 15°，第 3 关 25°——**这就是"偏多少度"的来源，不是手写的一个标签**。

### 这里踩过的坑（值得单独记）

第一版我们是这样量的：拿"母球→假想球"的方向，和"母球→球心"的方向求夹角。

算出来永远是 **0.5°**。因为假想球离球心只有 28 像素，两条方向线几乎是同一条——于是：

- 画面上"偏角关"看起来完全正常
- 但那个瞄准圈一直没画（我们设的条件是"大于 3° 才画"）
- 更糟的是，挡球还摆在"母球→球心"那条线上，等于**偏角根本没生效**

修正以后才明白：**15° 说的是"母球来的方向"和"目标球去的方向"之间的夹角**，量的是两条相隔很远的方向，不是两个相距 28 像素的点。

## 4. 一杆的生命周期：aim → fly → done

和主玩法一样三个阶段，但结算逻辑多了一层"杆数预算"：

```js
function finishShot() {
  const r = s.result;

  if (r && r.kind === 'ok' && r.potted) {
    s.phase = 'done';            // 进袋了：停在结算态，露出「下一关」
    // 记最好杆数、放音效、显示文案……
    return;
  }

  // 杆数用完了：这一关到此为止，只能点「重试」
  if (s.maxShots && s.attempts >= s.maxShots) {
    s.phase = 'done';
    return;
  }

  // 还有杆数：摆回本关原位，接着打下一杆
  const used = s.attempts;
  s = makeState(level);          // 重新造一遍局面（球都回原位）
  s.attempts = used;             // 但杆数是累计的
  s.phase = 'aim';
}
```

**为什么"每一杆都摆回原位"**：这样同一个谜题可以反复试，玩家学到的是"这一杆的解法"，而不是"球被我撞飞之后怎么收场"。摆回原位 + 累计杆数，就是"给你 3 次机会解同一道题"。

### 又一个坑

早期版本没写最后那段，`finishShot` 直接 `phase = 'done'` 就结束了。结果：

- 一杆没进 → 界面锁死 → 只能点「重试」
- 于是 `attempts` 永远是 1，"N 杆内过"这条规则**从来没用上过**

界面看起来一切正常（有文案、有重试按钮），但规则是假的。这类 bug 只能靠"整条流程走一遍"发现——所以第 6 节那套自动验证很重要。

## 5. 难度往哪儿加

我们最后定的是三关递进：

| 关 | 挡球 | 袋口偏角 | 杆数 | 目标球离袋口 | 定位 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 颗 | 0°（正对） | 不限 | 70 | 教学 |
| 2 | 3 颗 | 15° | 2 杆（手机 3） | 160 | 入门 |
| 3 | 4 颗 | 25° | 3 杆（手机 4） | 195 | 挑战 |

加难度我们走的是**两条腿**，一条管"算得准不准"，一条管"还有没有退路"：

- **算不准**：偏角越大越要精确打到假想球那个点上，容错被角度吃掉
- **选择少**：杆数越收越紧，挡球一颗颗加，错一次就少一次机会

四个可以拧的旋钮，按"加难度是否公平"排序：

1. **偏角**（15° → 25°）：几何变难，但给瞄准圈就不难了，属于"教学性难度"
2. **杆数**（不限 → 2 → 3）：最直接的压力，改一个数字就行
3. **挡球数量**（1 → 3 → 4）：多一颗挡球，弧线可容的区间就窄一截，还得算"先跨过哪颗"
4. **目标球离袋口的距离**（70 → 195）：同样歪 1 度，离得越远偏得越多，容错被真实压缩
5. **提示给多少**：最狠的一档，见下

关于第 5 个：**提示越全，难度越接近 0**。我们的预览会直接告诉你"这杆能跳过挡球、把 3 号送进袋"——等于把答案写出来了。

所以页头做了一个「**瞄准圈 开 / 关**」的小开关：

- **开**（默认）：目标球旁边画一个蓝色虚线圆 + 圈心点，告诉你"母球该停这儿"；拖拽时还会给落点圈、挡球上的红叉、底部"这杆能过 / 过不去"
- **关**：上面这些**圆圈和判断全收起**，只剩一条弧线（而且不再变红）加一句"力度 60%"——这杆行不行，自己看弧线落点判断；袋口那条淡金虚线、目标球和袋口上的金环照旧

注意"关"到底关掉了哪些东西，这一条容易做漏：假想圈只是第一个，落点圈、挡球红叉、红色弧线、"这杆能过"的文案，**全是同一类东西——"结论"**。只关假想圈、留着落点圈，玩家还是会觉得"圈没关干净"（我们第一版就是这么被打回来的）。

那为什么金线不跟着关？因为两种提示是**两种性质的信息**：

- 假想圈、落点圈、红叉是**技术信息**（"该打哪个点、这杆行不行"）——关掉它，玩家知道自己在干嘛，只是得自己算，这是公平的难度
- 金虚线与袋口 / 目标球金环是**任务信息**（"这一关要打哪个袋"）——关掉它，玩家连目标都不知道，那不是变难，是变盲猜

所以：**技术信息可以做开关，任务信息必须常驻**。以后你要给别的提示做分级，先问一句"关掉它，玩家还知道该干什么吗"，答案是否，就别关。

```js
// 假想圈
function drawGhostHint() {
  if (!hintOn) return;                        // 开关关掉就不画
  if (!s.ghost || s.cutDeg <= 3) return;      // 共线的第 1 关也不用画
  if (s.phase !== 'aim') return;              // 只在瞄准时出现
  // ……画圈 + 圈心小点
}

// 落点圈和挡球红叉（同一开关，在 drawAimPreview 里）
if (!hintOn) { ctx.restore(); return; }       // 弧线画完就收手
```

状态存进 `localStorage`，玩家关一次就一直记得：

```js
const HINT_KEY = 'eightball.jump.hint.v1';
let hintOn = true;
try { hintOn = localStorage.getItem(HINT_KEY) === '0' ? false : true; } catch (e) {}
```

**这就是"难度分级"最省事的做法**：不用改物理、不用加关卡，一个开关就让同一关多出一个档位。

### 移动端：两个不用改几何的适配

桌面上这套参数能玩，直接搬到手机上会"能玩但不好玩"。原因很具体：**满力是 84 个逻辑单位的拖拽距离**，画布在 1120 宽时这 84 就是 84 个 CSS 像素，可到了 430 宽的横屏手机上，整张画布被压缩到 0.38 倍——同样 20% 的力度窗口，落在地上只剩 **6 个 CSS 像素**。鼠标勉强能停住，手指基本不可能。

所以我们不改关卡几何，只改两处输入侧的参数：

```js
// ① 满力距离按「屏幕手感」算：画布被缩小多少，逻辑距离就放大多少
const maxDrag = MAX_DRAG * Math.max(1, cssScale);   // cssScale = VIEW_W / 画布显示宽度
const power = clamp(pull / maxDrag, 0, 1);
```

改完的效果：不管屏幕多宽，**都是拉 84 个 CSS 像素到满力**，那 20% 的窗口稳定在 17 个像素左右，手指能停住。桌面 `cssScale = 1`，行为完全不变。

```js
// ② 窄屏多给一杆，因为手指本来就比鼠标粗
function narrowScreen() { return cssScale > 1.5; }
function shotBudget(L) {
  if (!L.maxShots) return 0;
  return L.maxShots + (narrowScreen() ? 1 : 0);
}
```

| 关 | 桌面杆数 | 手机杆数 |
| --- | --- | --- |
| 1 | 不限 | 不限 |
| 2 | 2 杆 | 3 杆 |
| 3 | 3 杆 | 4 杆 |

顺带一个规范：**杆数不要写死在关卡文案里**。我们把 `hint` 只写"偏 15°"，杆数交给 `syncLevels()` 拼上去（`'，' + shotBudget(L) + ' 杆内过'`），否则手机上一改杆数，文案就开始撒谎。

还有第三处不属于"难度"、但属于"能不能看"：**手机横屏只有 300～400 px 高**，页头一换行，台面就被挤扁——球直接变成椭圆。这里有个很隐蔽的坑：

> `canvas` 放在 `display:flex` 的容器里时，默认 `align-items: stretch` 会把它**纵向拉满**。画布宽高比一旦被改，`ctx` 画的圆就变成椭圆。这个 bug 在桌面上永远看不到，只有屏幕够矮、容器被压到装不下时才会冒出来。

两条处理，都不碰物理：

- **页头/页脚在矮屏压成一行**：`@media (max-height:560px) and (orientation:landscape)` 里把标题改成单行 + 省略号，按钮缩到 22px 高，底部提示也单行省略
- **浮层宽度别用 `calc()` 猜**，改在 `resize()` 里量出来再反推：

```js
// 「页头 + 页脚 + 内边距」实际吃掉多少高，剩下的才是台面的
const chrome = head.offsetHeight + foot.offsetHeight + 内边距 + 间距 + 余量;
const maxW = (window.innerHeight - chrome) * (VIEW_W / VIEW_H);   // 1120 / 620
box.style.maxWidth = Math.round(maxW) + 'px';
```

因为宽度又会反过来影响页头是否换行，这个函数**连量两遍**再定格。量完的结果：844×390 横屏下浮层 513×363、台面 493×273，比例 1.81 正好，六颗袋口一颗不少。

## 6. 怎么验证（不碰鼠标也能跑完一杆）

问题：无头浏览器（`chrome --headless`）里 `requestAnimationFrame` 会被"虚拟时间"节流，一杆的物理可能只推进了几帧，截图永远是"刚起跳"的样子。

解决办法：给模块留一个**手动推进**的口子：

```js
function step(seconds) {
  let left = Math.min(Math.max(0, seconds), 8);
  while (left > 0 && s.phase === 'fly') {
    stepPhysics(1 / 60);       // 固定步长，结果完全可复现
    left -= 1 / 60;
  }
  if (s) draw();
}
```

于是可以写一张"力度扫描表"：30%、35%、…、90%，每一档打一杆、推到底、记下结果。跑一次就能看出**能过关的力度窗口**有多宽：

我们最后一版的实测结果：

- 第 1 关：**35%–55%** 能进袋（60% 母球自己掉袋，65% 以上空跑）
- 第 2、3 关：**65%–85%** 能进袋（60% 以下跳过去也滚不到目标球，90% 会飞过头）

有了这张表，"这关是不是太难"就不用靠感觉吵了——**窗口太窄就调距离或杆数，窗口跑飞了就查 bug**。

顺带一个反直觉的发现：我们给第 2、3 关各加了一颗近处挡球，原以为窗口会大幅收窄，结果窗口只是从 75%–90% **挪到了 65%–85%**，宽度几乎没变。也就是说——**挡球加得再多，"能不能进"靠的还是落点和角度，杆数预算才是真正在压缩容错的那个旋钮**。别指望加障碍就能让难度翻倍。

> 这一招不只用于跳球。任何"一杆出结果"的游戏（高尔夫、愤怒的小鸟）都可以这么测。

## 7. 容易踩的坑（六条，全是真踩过的）

1. **挡球不吃摩擦** → 它永远在"动"，`settle` 永远不到 0.2 秒，一杆永远不结算。
   改成：**所有贴地球都吃摩擦**，全场静止 0.2 秒才结算。
2. **满力会从袋口缺口窜出台面**（球跑到 `y = -112`）。
   加一个"别出桌"的兜底：超出边界就按台面边界反射回来。
3. **兜底和判袋的顺序**：一定要**先判袋、再兜底**。反了的话，贴库滑向袋口的球会在进袋前被弹回来。
4. **挡球被撞进袋里也算过关** → 碰到挡球那一刻就锁定结果（`blocked`），后面再怎么样都不算过。
5. **偏角算错**（第 3 节）：画面正常、规则失效，最阴的一类 bug。
6. **提示太多**：预览写成"这杆必进"，玩家就不用学了。提示要分层：给方向（袋口线）、给结果（能不能过），但**别给完整答案**（瞄准点也有开关）。

## 8. 动手练习

1. 加第 4 关：5 颗挡球、偏 32°、2 杆内过。**只改 `LEVELS` 这个数组**，一行物理都别动。
2. 把 `LEVELS` 搬出去，做成 `js/jump-levels.js`（或一个 JSON）。关卡变数据以后，加关就是加一段配置。
3. 给第 3 关换个目标球号（比如 7 号），看看提示文案会不会跟着变——如果不会，说明有地方把数字写死了。
4. 把 `LIFT`（0.30）改成 0.6 再打一杆：球看起来飞得更高，但落点圈会偏。想想为什么"画"和"算"必须是两套数。
5. 关掉「瞄准圈」打三杆，记下你实际打薄了多少度，和 `cutDeg` 比一比。你会发现"凭手感"和"算出来"差得比你想象的大。
