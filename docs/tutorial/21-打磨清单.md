# 第 21 章 · 打磨清单

**本章目标**：把"能玩"变成"好玩"。这一章不讲新功能，只讲**参数怎么定、坑怎么躲**。建议当手册收藏。

---

## 1. 手感参数表

这些数字没有公式，全是调出来的。**想改手感，只动这些地方（`js/config.js`）**。

| 参数 | 值 | 作用 | 调大会怎样 | 调小会怎样 |
| --- | --- | --- | --- | --- |
| `BALL_R` | 14 | 球半径 | 球更大，袋口相对变窄，更难 | 球小，视觉空，碰撞判定变细 |
| `MAX_SPEED` | 1250 | 满力球速 | 更暴力，更容易飞过袋口 | 打不到远端 |
| `MIN_SHOT_SPEED` | 150 | 最小出杆速度 | 轻杆也能走很远 | 轻杆几乎不动，易"空杆" |
| `ROLL_DECEL` | 200 | 台呢摩擦减速 | 滑得更远、更"滑" | 一碰就停，手感发闷 |
| `STOP_SPEED` | 7 | 判定静止的速度 | 停得慢、有"蠕行" | 突然刹停，像被吸住 |
| `CUSHION_RESTI` | 0.84 | 库边弹性 | 弹得活 | 撞库就泄力 |
| `BALL_RESTI` | 0.96 | 球球弹性 | 更脆、更响 | 像撞棉花 |
| `MAX_DRAG` | 84 | 满力所需拖拽距离 | 手指要拖更远 | 一碰就满力，难控 |
| `PHYS_DT` | 1/240 | 物理步长 | 更准但更耗 CPU | 可能穿球 |
| `CAPTURE_R` | 26 / 23 | 落袋判定半径 | 更容易进（也更容易"糊"） | 球在袋口悬着不进 |

**调参顺序建议**：先调 `ROLL_DECEL`（滑不滑）→ 再调 `MAX_SPEED`（够不够暴力）→ 最后调 `MAX_DRAG`（操作累不累）。

## 2. 几个"反直觉"的打磨点

### ① 拖动时不要显示"旧方向"的辅助线

早期版本空闲时也画一条辅助线，用户反馈"台面上老有一条灰线，像 bug"。现在的规则：**只有按下拖拽时才画**。

### ② 摆球时辅助线要指向最近的球

否则玩家把母球拖到对面，线会指向一片空白，看起来像坏了（第 13 章）。

### ③ 母球要"呼吸"

轮到你、但还没按下时，母球外画一圈很慢的光晕（2.8 秒一轮、透明度峰值 0.26）。作用是**让玩家一眼找到白球**。

参数调过一轮：原来是 0.9 秒一轮、alpha 0.5，用户说"太急、太跳"，改成慢而淡就舒服了。

### ④ 手中球要有个标签

母球旁边浮一个"按住母球拖动摆位"的小药丸。没有它，新玩家不知道现在可以摆球。

位置要自动避让：默认在球下方，**贴到底边或有球挡着就翻到上方**。

### ⑤ 提示时长按字数算

见第 18 章的公式。核心是：**用户不需要在 2 秒内读完 40 个字。**

### ⑥ 计时跟着台面走，不跟页面走

见第 18 章。教训一句话：**"居中"要对齐的是你想要的那个容器，不是整个页面。**

## 3. 我们回退过的设计（很重要）

失败的设计比成功的更值得记——**它们告诉你"为什么最后选了现在这个"**。

| 试过的方案 | 为什么放弃 |
| --- | --- |
| 右上角独立设置弹窗 | 挡台面，还要开关两层 |
| 开局大弹窗 | 每次进来都要点一次，烦 |
| 面板里加"常显示"开关 | 用户根本不想多一个开关，直接用页头按钮更好 |
| 桌面"沉浸模式" | 概念不清，用户更认"全屏" |
| 力度按 1/5 档位归一 | 台球要的是连续力度，档位很别扭 |
| 台面上画力度百分比在母球上 | 挡球、挡辅助线，信息也有冗余 |
| 面板状态卡里也显示计时 | 和台面那处重复，还挤状态行 |
| 页头中间放计时 | 面板一开就相对台面错位（最终挪到球号条中间） |
| 面板默认收起 | 第一次进来像"没做完"，用户找不到设置 |
| 收起面板时弹一次性提示 | 干扰，且提示本身又需要"记住不再弹"的机制 |

## 4. 20 条踩坑总表

按"症状 → 原因 → 解法"整理，遇到问题直接搜症状。

| # | 症状 | 原因 | 解法 |
| --- | --- | --- | --- |
| 1 | 球坐标变成 `NaN`，画面消失 | 两球心完全重合时 `dx/d` 除以 0 | 碰撞前 `if (d2 < 1e-6) return` |
| 2 | 两颗球粘在一起抖 | 只改速度、没分离重叠 | 先按 `overlap` 各退一半 |
| 3 | 球"越撞越快" | 冲量公式漏了 `0.5` | `imp = -(1+e)*rvn*0.5` |
| 4 | 球穿墙飞出台面 | 一帧 `dt` 太大 | 固定步长 `PHYS_DT` + `guard` 上限 |
| 5 | 手中球没松手就自己放下 | `pointercancel` 被当成 `pointerup` | 单独 `abortDrag()` 回滚 |
| 6 | 按下后游戏再也按不动 | 提前 `return` 没清 `activePointer`；或 `setPointerCapture` 抛错 | 清理状态 + `try/catch` |
| 7 | 拖动时页面跟着滚 | 没阻止默认行为 | `{ passive: false }` + `preventDefault()` |
| 8 | 点击位置偏一大截 | 直接用 `clientX` 当逻辑坐标 | `getBoundingClientRect` 换算 |
| 9 | 高清屏上球号发糊 | 画布没按 DPR 放大 | `setTransform(dpr,0,0,dpr,0,0)` |
| 10 | 改完 `canvas.width` 画面全白 | 重置画布会清掉所有绘制状态 | 重设变换 + 每帧重画 |
| 11 | 台面线条变细/断开 | 缩放后 `lineWidth` 变物理小数 | `lineWidth / cssScale` |
| 12 | 虚线画完，后面全变虚线 | 忘了 `restore()` | `save → setLineDash → restore` |
| 13 | 花色球后面全被裁掉 | `clip()` 之后没 `restore()` | 同上 |
| 14 | 辅助线穿过木框 | 只算了球没算库边 | 库边也做射线求交，取最小 |
| 15 | 落袋球还在原地显示 | 忘了跳过 `active === false` | 绘制循环里 `if (!b.active) return` |
| 16 | 球擦袋口就消失 | 判定半径等于视觉半径 | `CAPTURE_R < POCKET_R` |
| 17 | 一杆还没打完就换人 | 提前判胜负 | 等 `allStopped()` 再 `endShot()` |
| 18 | 上一杆进的球算到这一杆 | `state.shot` 没清空 | 结算完 `state.shot = null` |
| 19 | 计时重复累加 / 暂停后乱跳 | `clockSince` 没清零 | 两段式记账 `clockMs + clockSince` |
| 20 | 手机底部状态条被系统条盖住 | 没处理安全区 | `env(safe-area-inset-bottom)` |

## 5. 一条贯穿全项目的原则

**"算"和"画"分离。**

- `physics.js` 只改 `x / y / vx / vy`，绝不碰 `ctx`
- `render.js` 只读 `state.balls`，绝不改物理量
- `rules.js` 只读写 `state` 和 `shot`，绝不画像素

好处：

1. 改球的颜色不会影响碰撞
2. 可以用 `node` 直接跑物理测试（不需要浏览器）
3. 出 bug 时定位很快："坐标不对 → 看 physics；显示不对 → 看 render"

**如果你以后自己做游戏，请务必先建立这条边界。**

## 6. 练习

1. 打开 `js/config.js`，把 `ROLL_DECEL` 从 200 改到 120，打一杆感受"变滑"；再改到 320 感受"变粘"。
2. 把 `MAX_DRAG` 改成 60，感受"很容易满力"；改回 84。
3. 从上面 20 条坑里挑 3 条，在你的代码里**故意制造**一次，看能不能靠控制台报错误导自己找出来。
