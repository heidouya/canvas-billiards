# 第 4 章 · 网页的三层结构

**本章目标**：弄清 HTML / CSS / JS 各管什么；搞懂 `<canvas>` 和"画布尺寸"；理解本项目的文件拆分和脚本加载顺序，为什么不能乱。

**开始之前**：第 1–3 章。你现在能让 JS 打印东西了。

---

## 1. 三层分工

同一个网页，是三样东西叠出来的：

| 层 | 文件 | 管什么 | 台球里的例子 |
| --- | --- | --- | --- |
| HTML | `index.html` | **结构和内容**："这有一块画布""这有一个按钮" | 台面画布、右侧面板、球号条 |
| CSS | `css/*.css` | **外观**：颜色、圆角、间距、位置 | 面板深色、按钮圆角、球号小球 |
| JS | `js/*.js` | **行为和计算**：球怎么动、规则怎么判、点了会怎样 | 物理、规则、AI、计分 |

有一个判断标准很有用：

> **画在 canvas 上的东西，全是 JS 画的；其余界面元素，全是 HTML + CSS。**

台面上那 16 颗会动的球 —— 是 JS 一帧一帧画出来的（第 6 章）。
右侧"重新开局"按钮、球号条上的小圆点 —— 是 HTML 元素 + CSS 样式。

## 2. `<canvas>`：页面里的一块画板

在 `<body>` 里加一行：

```html
<canvas id="board" width="1120" height="620"></canvas>
```

`id` 是它的名字（后面 JS 靠名字找到它），`width` / `height` 是**画板的像素尺寸**。

JS 里这样拿它：

```html
<script>
  const canvas = document.getElementById('board');
  const ctx = canvas.getContext('2d');
  console.log(canvas.width, canvas.height);   // 1120 620
</script>
```

- `getElementById('board')` —— 按名字找页面元素
- `getContext('2d')` —— 拿到"2D 画笔"。之后 `ctx.fillRect`、`ctx.arc` 这些绘图命令都发给它

### 一个必须分清的差别

```html
<canvas width="1120" height="620" style="width: 560px"></canvas>
```

- `width="1120"` 是**画板内部有多少格**（逻辑像素）
- `style="width:560px"` 是**画板在页面上占多宽**（屏幕像素）

画板被压缩到 560 显示时，里面仍然是 1120 格。这正是我们要的：**逻辑坐标固定 1120×620，显示多大交给 CSS**。第 7 章专门讲这件事，现在只要记住"画板大小 ≠ 显示大小"。

## 3. 文件拆分：为什么是 17 个 js

如果你把所有代码塞进一个 `<script>`，走到第 2000 行时你会疯 —— 找一个"球撞库"的函数要翻半天。

本项目的拆法（`js/` 目录）：

```
config.js    常量：尺寸、袋口、物理参数、颜色         ← 最先加载
util.js      小工具：clamp、dist、颜色明暗
state.js     全局状态：球、回合、阶段
balls.js     造球、摆球
canvas.js    拿画布、处理清晰度
render.js    画台面、画球、画光晕
aim.js       瞄准方向、辅助线
physics.js   物理：摩擦、碰撞、库边、落袋
input.js     鼠标 / 触摸
rules.js     一杆的生命周期、规则、犯规
score.js     结算、战绩、弹窗
ai.js        电脑对手
sound.js     音效
replay.js    回放
hud.js       界面数字：状态、力度、计时、提示
loop.js      主循环
main.js      启动
```

三个原则：

1. **"算"和"画"分开。** `physics.js` 只改数字（`b.x`、`b.vx`），`render.js` 只负责把数字变成像素。这样你调球的颜色不会影响物理。
2. **常量集中。** 想改球大小？只动 `config.js` 一行。
3. **一个文件一件事。** 找 AI 就去 `ai.js`，不用全局搜索。

## 4. 脚本加载顺序：不能乱

在 `index.html` 末尾：

```html
<script src="js/config.js"></script>
<script src="js/util.js"></script>
<script src="js/state.js"></script>
...
<script src="js/main.js"></script>
```

浏览器是**从上往下、一行一行执行**的。所以：

- 先加载 `config.js`（定义 `BALL_R`、`TABLE`），后面的文件才能用这些常量
- `main.js` 放最后，因为它要"启动"整个游戏，得等别人都准备好了

**顺序错了会报 `xxx is not defined`** —— 名字还没定义就被用了。

### 为什么不用 import / export

现代 JS 有 `import` / `export` 模块系统，更规范。但本项目故意不用，原因很实际：

- 用 `import` 就必须走 http 服务器，`file://` 双击打开会被浏览器的安全策略拦住
- 我们要的就是"双击 `index.html` 就能玩"

代价是：所有文件里的变量都活在**同一个全局作用域**里，像在同一个房间说话。所以项目里变量名尽量独特（`PHYS_DT`、`AIM_SHORT_LEN`），避免撞名。

> 一句话记忆：**同一个页面里，17 个 js 就像 17 个人在一个房间，谁都能听见谁说话。**

## 5. 三个坑

1. **脚本放在元素之前。** 如果 `<script>` 写在 `<canvas>` 上方，执行到 `getElementById` 时画布还不存在，拿到的是 `null`，后面全崩。解决办法：脚本放 `</body>` 前（本项目就是），或者包进 `window.addEventListener('load', ...)`。
2. **`id` 拼错。** `getElementById('board')` 和 HTML 里 `id="board"` 必须一字不差，大小写也一样。
3. **CSS 里忘了单位。** `width: 560px` 的 `px` 不能省。

## 6. 动手练习

1. 建 `my-pool/index.html`，里面放一个 `canvas`，`width=1120 height=620`，用 CSS 让它显示为 `width:100%`（跟着窗口走）。刷新看看——画板还是空的，但已经撑开了。
2. 在 `<script>` 里用 `getElementById` 拿到画布，打印 `canvas.width` 和 `canvas.height`。
3. 把 `getContext('2d')` 拿到手，加一句 `ctx.fillStyle = '#2f9e57';` 和 `ctx.fillRect(60, 60, 1000, 500);` —— 你会看到一块绿色台面。**这就是第 5 章的开头。**
4. 故意把这个 `<script>` 挪到 `<canvas>` 前面，刷新，看控制台报错（`Cannot read properties of null`），再挪回去。
