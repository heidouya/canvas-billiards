# 第 20 章 · 手机与全屏

**本章目标**：让游戏在手机上竖屏能看、横屏能打；用浏览器全屏把纵向空间全留给台面；把面板变成右侧抽屉。

**开始之前**：第 7 章（自适应）、第 18 章（界面布局）。

---

## 1. 三套布局，只靠 CSS

同一份 HTML，用媒体查询切成三套：

| 场景 | 条件 | 布局 |
| --- | --- | --- |
| 桌面宽屏 | 宽 > 940 | 左边台面 + 右边 302/336px 面板 |
| 竖屏 / 平板 | 宽 ≤ 940 | 台面在上、面板在下，整页纵向滚动 |
| 手机横屏 | 高 ≤ 560 且宽 ≤ 1000 | 台面独占一屏，页头收起，只留细球号条 + 底部状态条 |

```css
@media (max-width: 940px) { ... }

@media (orientation: landscape) and (max-height: 560px) and (max-width: 1000px) { ... }
```

**为什么横屏要三个条件同时成立？** 因为"宽 1000、高 560"也可能是一个小笔记本窗口，它不该变成手机布局。加上 `orientation: landscape` 和高度限制，才准确定位到"手机横屏"。

## 2. 竖屏：把台面放大到能看清

手机上竖屏只有 390px 宽，台面硬塞进去球会小到看不清。策略是：

- 台面**宽度撑满**，高度按比例跟着来
- 面板整个移到下面，不再抢宽度
- 球号条变成"两组各占一半"，小球缩到 18px

```css
@media (max-width: 940px) {
  .rack-strip { gap: 6px; }
  .chip { width: 18px; height: 18px; font-size: 9px; }
  .group-panel { flex-direction: column; align-items: flex-start; }
}
```

再窄一档（≤560px）时，中间的本局计时也要收一收，否则会把 7 颗球号挤到换行：

```css
@media (max-width: 560px) {
  .rack-clock { flex: 0 0 46px; font-size: 13px; }
  .chip { width: 17px; height: 17px; }
}
```

> **这条是实测出来的**：430px 宽时，7 颗球号在 46px 的计时两侧刚刚好，一颗都不会被切。

## 3. 横屏：把纵向空间全给台面

横屏打台球的物理现实：手指要从左右两侧操作，屏幕不能太高（否则手掌够不到中间）。

所以要**把页头、面板、战绩全部收起来**：

```css
header { display: none; }                 /* 页头让位 */
.status-card {                            /* 底部固定一条状态条 */
  position: fixed; left: 0; right: 0; bottom: 0;
  flex-direction: row; align-items: center;
  padding: 5px 10px calc(5px + env(safe-area-inset-bottom, 0px));
}
```

`env(safe-area-inset-bottom)` 是 iPhone 底部的横条高度。不处理的话，状态条会被"小白条"盖住。

台面尺寸这样反算：

```css
.table-col {
  width: min(100%, calc((100dvh - 76px) * 1.8065));
  margin: 0 auto;
}
```

- `1.8065` 是 1120/620，保持宽高比
- `100dvh` 是"当前可视高度"（比 `100vh` 更准，因为手机浏览器地址栏会伸缩）
- `-76px` 是留给球号条和状态条的空间

结果：台面永远**最大化且不变形**，两侧留黑边。

## 4. 面板抽屉

窄屏上面板放不下，改成从右边滑出来：

```css
.panel {
  position: fixed; top: 0; right: calc(-1 * min(340px, 88vw));
  width: min(340px, 88vw); height: 100dvh;
  transition: right .22s ease;
}
body.panel-open .panel { right: 0; }
body.panel-open .panel-scrim { display: block; }   /* 半透明遮罩 */
```

```js
function togglePanel() {
  document.body.classList.toggle('panel-open');
}
```

配套两个细节：

- **点遮罩关闭**：`panel-scrim` 上绑 `click → closePanel()`
- **选完任意一项自动收起**：在设置项的回调里 `closePanel()`，否则玩家点完规则还得手动关

## 5. 浏览器全屏

```js
async function toggleFullscreen() {
  if (!document.fullscreenElement) {
    await document.documentElement.requestFullscreen();
  } else {
    await document.exitFullscreen();
  }
}
```

手机上要**竖屏提示 + 横屏全屏**组合拳：竖屏时页头会出现一条"建议横屏并全屏"的提示，点"知道了"记住不再出现。

```js
const ROTATE_KEY = 'eightball.rotateTip.v1';
if (localStorage.getItem(ROTATE_KEY) === '1') tip.hidden = true;
```

**注意 `requestFullscreen()` 必须在用户手势（点击）里调用**，不能在页面加载时自动执行，否则浏览器直接拒绝。

还有一个坑：iOS Safari 不支持 `requestFullscreen`（只有 iPad 部分支持），所以全屏按钮要"支持才显示"：

```js
if (!document.documentElement.requestFullscreen) btn.hidden = true;
```

## 6. 触屏的额外处理

| 问题 | 解法 |
| --- | --- |
| 拖动时页面滚动 | CSS `touch-action: none` 加在画布上 |
| 长按弹出"选择/保存图片"菜单 | `contextmenu` 阻止 + `-webkit-touch-callout: none` |
| 双击缩放 | `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` |
| 手指比鼠标粗，按不准 | 判定半径放大（第 12 章的 `2.6 * BALL_R`） |

## 7. 坑

1. **用 `100vh` 而不是 `100dvh`**：手机地址栏伸缩时会出现"台面底部被切掉 40px"。
2. **横屏布局里还留着桌面面板**（302px）：台面被压成一条，完全没法打。
3. **忘了 `safe-area-inset`**：iPhone 底部状态条被系统横条盖住。
4. **`requestFullscreen` 放在 `load` 里**自动调用：被浏览器拒绝，有时还会弹一个吓人的提示。

---

## 8. 练习

1. 浏览器窗口拖到 900px 宽，看布局是不是切成"台面在上、面板在下"。
2. 用手机（或开发者工具的设备模拟）打开，竖屏看提示条，横屏看全屏布局。
3. 横屏时点右上"面板"，确认抽屉滑出、点遮罩能关、选完规则自动关。
4. 把 `100dvh` 改回 `100vh`，在手机上对比台面底部有没有被切。
