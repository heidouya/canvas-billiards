# 第 19 章 · 音效与存档

**本章目标**：不用任何音频文件，用代码合成击球声、碰撞声、落袋声；把音效开关、辅助线档位、面板状态记进 `localStorage`。

**开始之前**：第 10 章（知道什么时候该响）、第 15 章（用过 localStorage 存战绩）。

---

## 1. 为什么不用 mp3

放三个 mp3 进仓库会有几个问题：

- 文件变大（每个几十 KB，还得考虑加载时机）
- 浏览器要求"用户交互后才能播放"，处理 autoplay 很烦
- 版权、编码格式兼容

**WebAudio 可以用代码直接"算"出一个声音**：给一个频率、一段时长、一个音量包络，就是"咚"。

```js
const ctx = new (window.AudioContext || window.webkitAudioContext)();
```

`AudioContext` 是浏览器里的"混音台"。它是懒创建的——**必须在用户第一次点击后才能创建/恢复**，否则被浏览器静音：

```js
function initSound() {
  if (ac) return;
  ac = new AudioContext();
}

function resumeSound() {
  if (ac && ac.state === 'suspended') ac.resume();
}
```

绑定在第一次按下：

```js
function onPointerDown(e) {
  Sound.init();
  Sound.resume();
  ...
}
```

## 2. 一个"咚"怎么写

```js
function blip(freq, dur, gain) {
  const osc = ac.createOscillator();   // 音源：正弦波
  const env = ac.createGain();         // 音量包络

  osc.type = 'triangle';               // 三角波比正弦更"实"一点
  osc.frequency.value = freq;

  env.gain.setValueAtTime(gain, ac.currentTime);
  env.gain.exponentialRampToValueAtTime(0.0001, ac.currentTime + dur);  // 音量快速衰减

  osc.connect(env).connect(ac.destination);
  osc.start();
  osc.stop(ac.currentTime + dur);
}
```

三要素：

- **`freq` 频率**：越高越"尖"，木头击球大约 180~320Hz
- **`dur` 时长**：碰撞 0.06 秒，落袋 0.18 秒
- **音量包络**：一开始最大，然后指数衰减到几乎为 0——这就是"咚"而不是"哔——"

`exponentialRampToValueAtTime` 的终值不能写 0（会报错），所以写 `0.0001`。

## 3. 三种声音

```js
function sfxCue(power) {
  // 出杆：力度越大越响、越低沉
  blip(180 + power * 40, 0.09, 0.16 + power * 0.18);
}

function sfxHit(strength) {
  // 球撞球：脆一点的高音，音量跟撞击强度走
  blip(420 + Math.random() * 60, 0.055, 0.05 + strength * 0.16);
}

function sfxPocket(isCue) {
  // 落袋：低沉的"咕"，母球落袋更闷
  blip(isCue ? 120 : 165, 0.18, 0.12);
}
```

调用点在物理代码里（第 9、10 章）：

```js
// collideBalls 里
sfxHit(Math.min(1, Math.abs(rvn) / 600));

// collideRails 里
sfxHit(Math.min(0.6, Math.abs(vn) / 900));

// pocketBall 里
sfxPocket(b.id === 0);
```

**音量跟速度挂钩**是这章最重要的一招：轻碰是"嗒"，猛撞是"啪"。真实的球就是这样，玩家一听就知道力度对不对。

## 4. 音效开关要记住

```js
const SOUND_KEY = 'eightball.sound.v1';

let soundOn = localStorage.getItem(SOUND_KEY) !== '0';   // 默认开
```

```js
function setSound(on) {
  soundOn = on;
  localStorage.setItem(SOUND_KEY, on ? '1' : '0');
  el('btnSound').textContent = '音效：' + (on ? '开' : '关');
}
```

每个发声函数开头先判断：

```js
function blip(...) {
  if (!soundOn || !ac) return;
  ...
}
```

**默认值是"开"**，因为玩家第一次玩就期待有声音。想关的人自己关，且下次记住。

## 5. localStorage 的六把锁

项目里存了 6 种设置，每种一个 key：

| key | 存什么 | 默认 |
| --- | --- | --- |
| `eightball.records.v1` | 战绩（各模式胜负） | 空 |
| `eightball.sound.v1` | 音效开/关 | 开 |
| `eightball.aim.v1` | 辅助线档位 full/short/off | full |
| `eightball.rule.v1` | 中式/美式 | cn |
| `eightball.panelShow.v1` | 桌面面板是否展开 | 展开 |
| `eightball.mode.v1` | 上次玩的模式 | ai |

> 这里原本还有第七个 `eightball.guide.v1`（"新手引导已看过"）。后来去掉了：它让引导只在人生第一局出现，**每局开球时反倒时有时无**。凡是"每次开局都该重新提示一次"的东西，就不该落盘。

三个工程习惯：

1. **都带 `.v1` 后缀**：以后数据结构变了，可以直接换成 `.v2`，老数据不再读，不会崩溃。
2. **读的时候永远给默认值**：`localStorage.getItem(k) || '默认'`，第一次打开的用户没有这些 key。
3. **存之前检查是不是字符串**：`localStorage` 只认字符串，对象要 `JSON.stringify`。

```js
function loadJSON(key, fallback) {
  try {
    const raw = localStorage.getItem(key);
    return raw ? JSON.parse(raw) : fallback;
  } catch (e) {
    return fallback;         // 数据坏了就当没有，别让整局崩掉
  }
}
```

**`try / catch` 很关键**：用户手动改过 localStorage、或者被别的脚本写坏了，`JSON.parse` 会抛异常。**一个小异常不该让游戏打不开。**

## 6. 读取时机

设置要在**第一次渲染之前**读好，否则会先闪一下默认状态再变：

```js
// main.js 启动顺序
loadSettings();     // 读 localStorage，应用规则/辅助线/音效/面板
buildChips();       // 生成球号
resetGame();        // 摆球、起表
requestAnimationFrame(frame);
```

**"先恢复设置，再生成界面"** —— 顺序反了就会看到"面板先展开又收起来"这种闪动。

## 7. 坑

1. **`AudioContext` 在页面加载时就创建**：被浏览器标记为"未授权"，全程静音。必须等用户交互。
2. **`exponentialRampToValueAtTime(0)`**：直接抛 `RangeError`。
3. **每次发声都 new 一个 oscillator 却不 stop**：几秒后几百个振荡器一起跑，页面开始卡。记得 `osc.stop(...)`。
4. **`localStorage` 在 `file://` 下的行为**：Chrome 里是按文件路径隔离的，你把项目复制到另一个文件夹，设置和战绩会"丢"——这是正常的，不是 bug。

### 7.1 一堆小声音叠起来会"破音"

这条是我们真踩进去的坑，现象很怪：正常击球没毛病，**偶尔**球堆一炸就听到一声"沙"的杂音，像是扬声器坏了。

原因是硬件 / 浏览器的输出范围是 `[-1, 1]`，而我们每条声音都是**直接连 `destination`** 的独立支路。开球时十来颗球在 100 毫秒内互相撞，每条 `hit` 的峰值 0.05～0.25，二十来条声音同时在放，同一瞬间的波形加起来能到 **2.6～3.4**——超出 1 的部分被硬削平，削出来的方肩就是刺耳的高频"沙沙"。

实测（10 次满力开球，每次统计 20 ms 窗口内的叠加峰值）：

| | 改前 | 改后 |
|---|---|---|
| 20 ms 峰值 | 2.7～3.4 | 0.2～0.6 |
| 削波的局数 | 10 / 10 | 0 / 10 |
| 每杆 `hit` 触发 → 发声 | 28.2 条触发，全部发声（其中约 8 条低于听阈、白跑） | 28.2 条触发 → 约 21 条过听阈 → 合成约 7 声 |

三步修法，都不动玩法：

```js
// 1. 所有声音先过一条总线：降一点总增益，再用软膝压缩器兜峰值
const g = ctx.createGain();  g.gain.value = 0.85;
const comp = ctx.createDynamicsCompressor();
comp.threshold.value = -6; comp.knee.value = 12; comp.ratio.value = 3;
g.connect(comp); comp.connect(ctx.destination);

// 2. 同一瞬间的一簇撞击只留最响的那声（6 ms 内，约等于一个物理子步）
if (t - this._hitAt < 0.006 && v <= this._hitVol) return;

// 3. 强度低于听阈（v < 0.10）的接触直接不发
if (v < 0.10) return;
```

顺带把噪声 buffer 缓存起来（同长度的衰减包络是固定的，没必要每条撞击都重生成一块）。

### 7.2 "球滚动时的杂音"是怎么来的

上面那步解决了削波，但还有一路更阴的：**只出现在球滚动的时候**，断断续续"咻、咻"的一串。

先排除一个直觉假设：球单纯在滚，物理层是**一条音效都不发**的（我们挂上钩子实测过：贴库滚 3 秒 0 条、慢球穿袋口 0 条、三球相贴一起缓滚 2 条且强度低到听不见）。所以声音不可能来自"滚动本身"。

真正发声的，是**滚动期散落的那一簇低速碰撞**。以 62% 力开球实测，一杆 23 次碰撞里，有 10 次的强度 `v < 0.1`，而且挨得很近（相邻间隔中位数不到 60 ms）。旧版给**每一次**碰撞都发一条"高频下滑音"（`760 + v·620` 扫到 420 Hz，46 ms），一串叠在一起，听感就是粗糙的"咻咻/沙沙"——正好落在球还在滚的那一段，所以你会觉得"杂音只在滚动时出现"。

两条修正：

```js
const soft = v < 0.3;               // 轻碰单独走一套音色
const gap  = soft ? 0.025 : 0.006;  // 轻碰散得开，合流窗口放宽，否则连成一串"咔咔"
if (t - this._hitAt < gap && v <= this._hitVol) return;
if (soft) this.tone(480 + v * 420, 0.028 + v * 0.02, 0.03 + v * 0.14);  // 短、低、不下滑
else      this.tone(760 + v * 620, 0.045 + v * 0.03, 0.05 + v * 0.20, 'triangle', 420);
```

改前改后（同一杆 62% 力开球，实际发声条数）：

| 力度 | 碰撞次数 | 其中 v<0.1 | 旧版发声 | 新版发声 |
|---|---|---|---|---|
| 42% | 6 | 1 | 6 | 2 |
| 52% | 16 | 6 | 16 | 4 |
| 62% | 23 | 10 | 23 | 3 |
| 100% | 31 | 10 | 31 | 7 |

> 一个通用判断：**"滚动时的杂音"往往不是滚动音，而是滚动期那批小事件各自带出的、设计得过于"有音色"的声音**。轻碰就该是闷而短的，不该有滑音；先按强度分档，再按间隔合并，杂音自然消失。

> 一个通用判断：**只要你的音频是"多个独立支路直连 destination"，就迟早会遇到削波**。单声道的游戏音效还好，一簇撞击、机枪扫射、爆炸连锁，都会撞上同一堵墙。先上总线，再谈音色。
