# 第 8 章 · 让球动起来

**本章目标**：写一个动画循环，让母球带着速度往前跑、慢慢减速、最后停下；理解"固定步长"为什么能防穿墙。

**开始之前**：第 5–7 章。现在球能画出来了，但不会动。

---

## 1. 动画的本质：一秒钟重画 60 次

没有"移动"这回事，只有"每秒重画很多张位置略有不同的图"。

```js
function frame() {
  draw();                       // 重画整个台面
  requestAnimationFrame(frame); // 请求下一帧接着来
}
frame();
```

`requestAnimationFrame(frame)`（简称 rAF）的意思是"浏览器下次刷新屏幕前，帮我把 `frame` 再调一次"。通常是每秒 60 次，但有时会掉到 30、有时会卡一下——**所以每帧过了多久，必须由浏览器告诉我们，不能假设。**

```js
let last = performance.now();
function frame(now) {
  const dt = (now - last) / 1000;   // 这一帧过了多少秒（0.016 之类）
  last = now;
  step(dt);      // 用 dt 推进物理
  draw();        // 画出来
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

`performance.now()` 是"页面打开到现在过了多少毫秒"，比 `Date.now()` 精度高。

> 为什么用秒不用毫秒？因为速度是按"每秒多少像素"定义的，物理公式里时间单位是秒。

---

## 2. 速度、位移、摩擦

一颗球的状态就两个数字：`vx`（横向速度）、`vy`（纵向速度），单位是"逻辑像素/秒"。

```js
b.x += b.vx * dt;   // 位移 = 速度 × 时间
b.y += b.vy * dt;
```

如果 `vx = 600`（每秒跑 600 逻辑像素），一帧 1/60 秒就走 10 像素。

台球会慢慢停下来，因为台呢有摩擦。最简单可靠的模型是**匀减速**：

```js
const ROLL_DECEL = 200;          // 每秒掉 200 的速度
const STOP_SPEED = 7;            // 低于这个速度就直接当静止

function moveBall(b, dt) {
  const sp = Math.hypot(b.vx, b.vy);    // 当前速度大小
  if (sp === 0) return;

  const ns = sp - ROLL_DECEL * dt;      // 减速后的速度大小
  if (ns <= STOP_SPEED) {
    b.vx = 0; b.vy = 0;                 // 停住
    return;
  }
  const k = ns / sp;                    // 缩放比例
  b.vx *= k;                            // 方向不变，长度变成 ns
  b.vy *= k;

  b.x += b.vx * dt;
  b.y += b.vy * dt;
}
```

**为什么要把速度"等比缩放"而不是直接减？** 因为 `vx / vy` 决定方向。你只想让它变慢，不想让它拐弯。`k = 新速度 / 旧速度`，两个分量同比例缩，方向自然不变。

现实中球速 1250 时一杆能跑很远，用 `STOP_SPEED = 7` 卡一下，可以避免"看起来很慢还在挪"的那种粘滞感。

## 3. 固定步长：游戏稳定的秘密

直接拿每帧的 `dt`（0.016、0.017、偶尔 0.05）去算物理，会有两个问题：

1. **不同电脑算出的结果不一样**：跑得快和跑得慢，球的落点会有差别。
2. **偶尔一帧卡一下（dt 变大），球一下就跳过半个球直径，直接穿到对面去**——这叫**隧穿**。

解法：**物理永远用固定的小步长推进，攒够一步算一步。**

```js
const PHYS_DT = 1 / 240;    // 每步 4.17 毫秒
let acc = 0;

function stepPhysics(dt) {
  acc += dt;
  let guard = 0;
  while (acc >= PHYS_DT && guard < 80) {
    substep(PHYS_DT);       // 真正的物理计算
    acc -= PHYS_DT;
    guard++;
  }
  if (guard >= 80) acc = 0; // 防止长时间挂起后一次性补算 5000 步卡死
}
```

- 一帧 1/60 秒，会跑 4 个 `PHYS_DT` 步（`1/60 ÷ 1/240 = 4`）
- 即使这一帧慢了 3 倍，也只是多跑几步，**每步仍然只有 4 毫秒**，球不会瞬移
- `guard` 是保险绳：页面被切到后台几分钟后回来，`dt` 可能是几百秒，不设上限会卡死

这就是 `js/physics.js` 的 `stepPhysics` 和 `js/loop.js`。**"固定步长"这四个字，值得记住一辈子**，几乎所有游戏引擎都这么干。

## 4. 合起来：一颗会跑的球

在上一章的 `table.html` 里，替换成这个（完整可跑）：

```html
<canvas id="board" width="1120" height="620"></canvas>
<script>
const canvas = document.getElementById('board');
const ctx = canvas.getContext('2d');
const VIEW_W = 1120, VIEW_H = 620;
const BALL_R = 14;
const ROLL_DECEL = 200, STOP_SPEED = 7, PHYS_DT = 1 / 240;

const table = { x: 60, y: 60, w: 1000, h: 500 };
const balls = [
  { id: 0, x: 260, y: 310, vx: 600, vy: 0, active: true },
  { id: 1, x: 794, y: 310, vx: 0, vy: 0, active: true }
];

let acc = 0;
function substep(dt) {
  balls.forEach(function (b) {
    if (!b.active) return;
    const sp = Math.hypot(b.vx, b.vy);
    if (sp === 0) return;
    const ns = sp - ROLL_DECEL * dt;
    if (ns <= STOP_SPEED) { b.vx = 0; b.vy = 0; return; }
    const k = ns / sp;
    b.vx *= k; b.vy *= k;
    b.x += b.vx * dt; b.y += b.vy * dt;
  });
}

function draw() {
  ctx.fillStyle = '#1f7a52';
  ctx.fillRect(table.x, table.y, table.w, table.h);
  balls.forEach(function (b) {
    if (!b.active) return;
    ctx.beginPath();
    ctx.arc(b.x, b.y, BALL_R, 0, Math.PI * 2);
    ctx.fillStyle = b.id === 0 ? '#f8f6ef' : '#f2c53d';
    ctx.fill();
  });
}

let last = performance.now();
function frame(now) {
  const dt = Math.min(0.1, (now - last) / 1000);   // 单帧最多算 0.1 秒
  last = now;
  acc += dt;
  let guard = 0;
  while (acc >= PHYS_DT && guard < 80) { substep(PHYS_DT); acc -= PHYS_DT; guard++; }
  draw();
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
</script>
```

打开后：白球以 600 的速度向右跑，越跑越慢，大约 3 秒后停住。

**现在把 `ROLL_DECEL` 改成 60，再跑一次。** 球会滑得更远——摩擦系数对"手感"的影响，你立刻就懂了。这个参数调了几十次，项目最后定在 200。

## 5. 坑

1. **忘了 `requestAnimationFrame(frame)` 写在函数末尾**，只跑一帧就停。
2. **`dt` 没有上限**：切后台再回来，一下跑几十秒，球瞬移出去。项目里 `loop.js` 用 `Math.min(0.1, dt)` 兜底。
3. **把 `vx`、`vy` 当成像素/帧**。单位是"像素/秒"，乘 `dt` 才是位移。
4. **速度归零后还在算位移**：`k = 0/0` 会得到 `NaN`，球坐标变成 `NaN`，整个画面消失。所以先判断 `sp === 0` 就 `return`。

## 6. 练习

1. 给母球一个斜向速度 `vx = 400, vy = -300`，看它是不是沿斜线走。
2. 把 `STOP_SPEED` 改成 40，感受"提前停住"的假；改成 1，感受"永远在慢慢挪"。
3. 把 `PHYS_DT` 改成 `1/60`，然后一帧只算一步，看看高速球会不会穿墙（第 10 章加库边后试）。
